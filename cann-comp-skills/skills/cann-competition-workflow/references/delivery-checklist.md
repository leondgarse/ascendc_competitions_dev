# 验收交付件清单

任务书"验收交付件"表通常是这 4 项，逐项对照：

## 1. 算子设计文档
- [ ] 用 competitions 仓模板
- [ ] PR 提到 `cann-ops-competitions` 对应任务目录
- [ ] **已通过评审合入**

## 2. 自测用例及测试代码
- [ ] 覆盖任务书"自验证用例"表的每一类场景（无需穷举全部参数组合）
- [ ] README 说明环境、编译、测试步骤，**保证验收人可复现**
- [ ] 提供精度/性能测试代码；有专项类型（如 complex64）要有专项用例
- [ ] 优先复用任务书 `*_testCase/` 已给的用例、基线 CSV 和脚本

## 3. 自测报告
- [ ] 用腾讯文档模板（任务书给链接）
- [ ] 含：用例参数、精度结果+截图、性能数据+截图、**Profiler 证据**、失败项说明
- [ ] **记录实际使用的 CANN 版本**（任务书明确要求）

## 4. 待验收代码地址
- [ ] **个人 fork** 仓链接 + 分支 + 算子目录
- [ ] **邀请账号 `Ascend-CANN` 作为开发者**（任务书配图说明）
- [ ] 按仓库规范提供 README、接口说明、限制说明

## 性能采集口径（任务书常见要求）
- [ ] 预热 ≥10 次，正式采样 ≥30 次
- [ ] 报**中位数**和 **P90**
- [ ] 每轮**设备同步后**计时
- [ ] **不含**首次编译、数据生成、H2D 搬运、无关初始化
- [ ] 描述符/workspace/preprocess 结果在正式采样期间复用；preprocess 一次性耗时另报
- [ ] Profiler 证据证明**核心计算未回退 CPU**

## 精度口径
- [ ] 单标杆 CPU Golden：fp16/bf16 → fp32 算；fp32 → fp64 算；complex64 → complex128 算
- [ ] 逐元素 `|actual-golden| ≤ atol + rtol×|golden|`
- [ ] 整体匹配率 ≥ 0.99，且每元素绝对误差 ≤ `max(A, 32×ULP(golden))`
- [ ] complex64 的实部/虚部分别按 fp32 参数比对，两者都要达标
- [ ] 覆盖普通值/小值/正负混合/零值/离群值/INF/NAN

## 提交前
- [ ] `sh scripts/oat_check.sh <变更文件>` 通过
- [ ] `repo-coding-rules/references/checklist.md` 8 步全 PASS
- [ ] 无二进制文件、无公网地址、许可证头齐全

## 回归防护（血的教训）

- [ ] **任何触及 buffer 布局 / 偏移量 / tile 尺寸的改动，必须重跑完整用例集**，
      哪怕改动动机纯粹是"瘦身"、预期零功能影响。
- [ ] **正则批量替换偏移量是高危操作。** 真实事故：
      把 diag kernel 里的 plane 偏移从 `maxCnt_` 批量改成 `tileCnt_`，
      但 host 侧 gather 表仍按 maxCnt 跨距排布，两者不再匹配。
      只在 `n < 8` 时暴露（tileCnt_=8 ≠ maxCnt_=1024），
      小 smoke 集跑不到，直到换一台机器跑才发现 12/84 失败。
- [ ] **性能优化 commit 要有实测数字支撑，否则直接 revert。**
      上述改动实测零收益（改前改后都是 18.30us）——
      它引入的风险从一开始就没有对价。
- [ ] 至少在**两台独立 devenv** 上各跑一次完整用例集再交付。
      同一台机器的重复运行不能发现构建/环境相关的差异。

## 跨机器复现（性能结论必备）

- [ ] 关键性能结论在**第二台独立 devenv** 上复现后才写进文档
- [ ] 记录两台机器的 `npu-smi` 型号、CANN 版本、host 核数
- [ ] 逐点对比表，标注差异百分比；差异 <2% 才能称"平台特性"而非"本机异常"
